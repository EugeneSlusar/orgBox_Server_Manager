# orgBox Server Manager

Лёгкий терминальный мониторинг Linux с графиками CPU / RAM / диска и пользовательскими командами. Устанавливается **для текущего пользователя** в `~/orgbox_server_manager`, без `sudo`, Docker, SQLite, Python, Grafana и открытых портов.

> **Важно:** первая строка скачивает и запускает Bash-код из GitHub. Перед использованием на важных серверах можно [просмотреть установщик](install.sh) или сначала скачать его и проверить вручную. Запускай под тем пользователем, которому нужен мониторинг, например `dev`, **не под `root`**, если не хочешь установить для root.

## Проверка обновлений

При **каждом интерактивном запуске** `manager.sh` (в том числе при входе по SSH) скрипт один раз обращается к GitHub Releases и сравнивает текущую версию с последним опубликованным релизом. Если версия новее, предлагает обновить её с подтверждением `[y/N]`. При отказе продолжает работу как обычно. Если GitHub недоступен, через 6 секунд максимум продолжает запуск без ошибки. Сбор метрик через `collect`, установка и планировщик **не проверяют обновления** и не выполняют сетевых запросов. Настройки `manager.conf` и история `manager.csv` сохраняются.

Версия хранится в `~/orgbox_server_manager/VERSION`, создаётся установщиком при установке по тегу релиза. Обновления ищутся среди **опубликованных GitHub Releases**, не по коммитам ветки `main`. Изменения этой функции пока находятся в `main` и появятся в автоматических обновлениях после публикации следующего релиза.

## Быстрый старт

Выполни первую команду README в SSH-терминале — она устанавливает фиксированный релиз v0.3.0. Если используешь другую оболочку или хочешь проверить содержимое установщика перед запуском:

```bash
curl -fsSLo /tmp/orgbox-install.sh https://raw.githubusercontent.com/EugeneSlusar/orgBox_Server_Manager/main/install.sh
less /tmp/orgbox-install.sh
bash /tmp/orgbox-install.sh
```

После установки переподключись по SSH: монитор откроется автоматически. Открыть вручную:

```bash
~/orgbox_server_manager/manager.sh monitor
```

Монитор по умолчанию показывает LIVE-полоски и **вертикальные графики за 72 часа**. Клавиши `1`, `2`, `3` — 24 часа, 3 дня и 7 дней; `e` — редактировать настройки; `q` — перейти в обычный Bash; `x` — выйти из менеджера. При первом запуске историю ещё нужно накопить.

[Релизы GitHub](https://github.com/EugeneSlusar/orgBox_Server_Manager/releases). Для установки конкретной версии (после публикации соответствующего тега):

```bash
curl -fsSL https://raw.githubusercontent.com/EugeneSlusar/orgBox_Server_Manager/v0.3.0/install.sh | ORGBOX_VERSION=v0.3.0 bash
```

Установщик сохраняет существующие `manager.conf` и `manager.csv`. При повторном запуске обновляет `manager.sh` и регистрацию автоматического сбора; уже созданные пункты меню не удаляет. Версия `main` получает последние опубликованные изменения в основной ветке; для стабильного окружения рекомендуется фиксированный релиз.

## Файлы после установки

```text
$HOME/orgbox_server_manager/
├── manager.sh       # Мониторинг, меню, collect/install/uninstall
├── manager.conf     # Настройки текущего сервера
└── manager.csv      # История (создаётся после первого сбора)
```

Служебные файлы `.manager.lock/` и `.manager-rotation` создаются автоматически и не требуют редактирования. История не публикуется в репозитории.

## Диски и компактные графики

Начиная с v0.3.0, графики по умолчанию имеют высоту **5 строк**. Для уже установленных конфигураций с `GRAPH_HEIGHT=10` значение сохраняется — поменяй его на `5` в `~/orgbox_server_manager/manager.conf`.

Главный экран показывает до пяти локальных физических файловых систем, обнаруженных через `df -P -k -l`, с процентом заполнения и доступным объёмом. Виртуальные `tmpfs` и `overlay` исключены, одинаковые устройства не дублируются. Клавиша **d** открывает полный список и историю выбранного раздела; **n/p** переключают разделы, **q** возвращает на главный экран.

Новая история пишется в `disks.csv` (timestamp,mountpoint,used_percent,free_bytes). Прежний `manager.csv` и график корневого раздела сохраняются; оба CSV очищаются от записей старше `HISTORY_DAYS`. На некоторых контейнерных VPS корень `/` расположен на overlay — он останется в основном графике, но не будет показан в списке физических дисков.

При запуске интерактивного монитора экран очищается один раз; последующие обновления выполняются без предварительной полной очистки терминала: курсор возвращается в начало, а оставшиеся старые строки стираются после отрисовки. Это уменьшает мерцание. Для существующих установок параметр `REFRESH_SECONDS` в `manager.conf` не перезаписывается: установи `REFRESH_SECONDS=3` вручную.

## Графики и запись метрик

* `CPU` — загрузка **всей системы**, рассчитанная из `/proc/stat` за короткий интервал (~0,25 с).
* `RAM` — доля занятой памяти по `MemTotal` и `MemAvailable` из `/proc/meminfo`.
* `DISK /` — занятое место на корневой файловой системе по `df -P /`.
* LIVE обновляется каждые 3 секунды (можно настроить).
* История собирается раз в минуту, если установлен пользовательский cron либо доступен `systemd --user`.
* Каждый столбик — **максимум зарегистрированных замеров** за соответствующий временной интервал; высота от 0 до 100%, с подписью периода. Короткие всплески **между** замерами не гарантированно фиксируются.
* Раз в сутки CSV автоматически очищается от измерений старше 30 дней (настраивается). Очистка атомарная, сбор защищён файловой блокировкой.

Размер за 30 дней — обычно несколько мегабайт. Нагрузка минимальна: один краткий замер каждую минуту. Учитывай, что на VPS у одного пользователя доступ к системным метрикам может отличаться от shared-хостинга: там CPU и RAM могут отражать **весь хост**, а не лимиты аккаунта, или `/proc` может быть недоступен.

## Настройка пунктов меню

Открой `nano ~/orgbox_server_manager/manager.conf` либо нажми `e` в дашборде. Пример:

```ini
SERVER_NAME="orgBox AI Gateway"
DEFAULT_PERIOD=72
REFRESH_SECONDS=3
GRAPH_HEIGHT=5
HISTORY_DAYS=30
SAMPLE_SECONDS=60

# клавиша | подпись | shell-команда
s | Состояние | uptime; free -h; df -h /
o | OpenCode | opencode
t | tmux | tmux new -A -s opencode
# b | BitrixVM | /реальный/путь/к/menu.sh
# z | Docker | docker ps
```

`manager.conf` **не выполняется через `source`**: параметры разбираются как текст; пользовательская shell-команда исполняется **только при выборе соответствующей клавиши** от текущего пользователя. Не разрешай посторонним изменять конфигурацию. Клавиши `1`, `2`, `3`, `r`, `e`, `q`, `x`, `d` зарезервированы.

На BitrixVM добавь пункт с реальным путём к штатному меню. **Никакой `menu.sh` Битрикса скрипт не переписывает**. У некоторых сборок BitrixVM штатное меню вызывается при входе раньше `.bashrc`: потребуется отдельно настроить порядок запуска, не заменяя служебные скрипты Битрикса.

## Команды

```bash
~/orgbox_server_manager/manager.sh                  # монитор (интерактивный терминал)
~/orgbox_server_manager/manager.sh monitor 24       # последние 24 ч
~/orgbox_server_manager/manager.sh monitor 72       # 3 дня
~/orgbox_server_manager/manager.sh monitor 168      # 7 дней
~/orgbox_server_manager/manager.sh collect           # разовый замер (для cron)
~/orgbox_server_manager/manager.sh install           # повторно настроить автозапуск и сбор
~/orgbox_server_manager/manager.sh uninstall         # отключить автозапуск и планировщик
```

Сбор работает под тем же Unix-пользователем, что и установка. При наличии `cron` добавляется запись **в его crontab**. Если `cron` нет, но доступен пользовательский systemd, создаётся пара `orgbox-manager.service`/`.timer` в `~/.config/systemd/user/`; для работы после выхода из SSH может понадобиться `loginctl enable-linger ИМЯ_ПОЛЬЗОВАТЕЛЯ` от администратора. На хостинге без планировщика можно вручную добавить задачу `bash "$HOME/orgbox_server_manager/manager.sh" collect` через панель управления хостингом.

## Удаление

```bash
~/orgbox_server_manager/manager.sh uninstall
```

Команда удаляет только созданную вставку из `~/.bashrc`, запись cron и пользовательский systemd-таймер. Она **не удаляет** историю, настройки или саму папку. После проверки папку можно удалить вручную.

## Требования и ограничения

* Linux, Bash 4+, `awk`, `date`, `df`, `sed`, `grep`, `mktemp`, `curl` (**curl нужен только для удалённой установки**). Основные утилиты обычно уже есть в Ubuntu/BitrixVM.
* Доступ к `/proc/stat` и `/proc/meminfo` для CPU/RAM.
* Интерактивный SSH-терминал с поддержкой Unicode; для автоматической истории — cron или пользовательский systemd.
* Без `sudo`, открытия портов, изменения Nginx/Docker/Bitrix или доступа к данным другого пользователя.
* `.bashrc` — автозапуск только для интерактивных SSH-сеансов; не запускается для cron или `scp`.
* Дашборд с графиками по 5 строк занимает примерно 30–40 строк. На узких и низких терминалах нужно прокрутить вывод; при желании уменьшай `GRAPH_HEIGHT` до 4–8.
